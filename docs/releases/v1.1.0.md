# v1.1.0 — Daily AI cost optimisation and credit monitoring

Released 8 October 2026. This release moves daily writing from GPT-5 Mini to GPT-6 Luna while retaining GPT-5 Nano for relevance and classification. It also includes the organisation-cost-based credit monitor introduced immediately before the model migration. The implementation commit is `bcca649161d8f2227065256f8e43991140db0ad1`; the release includes a subsequent documentation refresh.

## Problem and resulting behaviour

The daily workflow pays for several distinct tasks: deciding whether an article is relevant, assigning a topic, summarising accepted articles, composing the digest, and writing LinkedIn text. Historical July–October exports showed that Mini accounted for approximately 92% of text-model spending and output tokens accounted for approximately 90%. Replacing every model with its newer namesake would not necessarily reduce cost. September usage repriced with GPT-5.4 Mini/Nano would have cost approximately $4.00, compared with the existing $1.67.

This release selects models by task and verified prices. GPT-6 Luna handles article summaries, digest composition and LinkedIn text. GPT-5 Nano continues to handle relevance and classification, preserving the inexpensive gate before writing calls. The LinkedIn banner still comes from the PIL template renderer; configured image-generation and Ollama models are not used by the inspected daily path.

| Stage | Before | v1.1.0 |
|---|---|---|
| Relevance | GPT-5 Nano | GPT-5 Nano |
| Classification | GPT-5 Nano | GPT-5 Nano |
| Article summary | GPT-5 Mini | GPT-6 Luna |
| Digest composition | GPT-5 Mini | GPT-6 Luna |
| LinkedIn text | GPT-5 Mini | GPT-6 Luna |
| LinkedIn banner | Template renderer | Template renderer |

The scheduled run remains 08:00 Europe/London. The migration does not republish today's digest; tomorrow's scheduled run reads the new settings.

## Historical cost simulation

The simulation reprices the four supplied completion-usage exports using their recorded uncached input, cached input and output tokens. UTC bucket dates determine the reporting month; the September-named export includes 1 October. The single ordinary-tier historical row retains ordinary-tier pricing. The September baseline reconstructs $1.665591375, previously reconciled against the organisation Costs API.

| Allocation | Simulated September USD | Change from baseline |
|---|---:|---:|
| Existing Mini + Nano | 1.665591 | — |
| Luna for Mini roles; retain Nano | **0.543909** | **−67.3%** |
| Luna for both Mini and Nano roles | 0.594154 | −64.3% |
| GPT-5.6 Luna for Mini roles; retain Nano | 1.085144 | −34.8% |
| GPT-5.4 Mini + GPT-5.4 Nano | 3.999233 | +140.1% |
| GPT-5.6 Terra for Mini roles; GPT-5.6 Luna for Nano roles | 9.889018 | +493.7% |

The selected allocation saves about $1.12 per month at the observed September volumes. This is a price simulation with unchanged token counts, not a future invoice guarantee. Models can use different output lengths and reasoning budgets; cache writes, cache hits, additional consumers and ordinary-tier fallback can change actual spending. The exports represent organisation usage and are not an exclusive project billing ledger.

For the healthy recent period of 1 September–6 October, simulated average cost changes from approximately $0.05506/day to $0.01796/day. A $1 reserve consequently represents about 18 days at the former average or 56 days at the simulated new average. Neither number is used as a measured account balance or a guaranteed exhaustion date.

## Request compatibility and output control

The common request path now handles GPT-6 Luna explicitly. It omits temperature, selects `reasoning_effort=none`, and applies an 8,192-token completion cap. Short summaries and bounded digest chunks should not inherit medium reasoning and its extra billed tokens without a deliberate decision. Luna's application cache key includes the reasoning setting and completion limit, preventing responses generated under different settings from sharing the same key.

JSON-writing calls request JSON object mode. They validate that the response is an object and reject empty output or a `length`/`content_filter` termination. This is JSON-mode validation, not a strict application schema: content requirements are still enforced by prompts and downstream processing. LinkedIn text continues to use plain-text output.

Capacity-related Flex 429 responses retry on ordinary processing using the API-supported `default` tier. Legacy `standard` settings are normalised at the request boundary. Quota exhaustion is not treated as a capacity fallback. Costs use the returned processing tier rather than assuming the configured Flex tier was used.

## Editorial grounding

The summary prompt advances to v2. Summary, digest and LinkedIn instructions tell the model to use supplied facts, ignore navigation/adverts and avoid inventing names, figures, causes or confirmed business outcomes. Digest and LinkedIn implications must be qualified as possibilities.

A substantive article should produce three to five concise factual summary bullets. A headline-only or incomplete source may produce one or two supported facts with a brief note that detail is limited; an input containing no article facts may produce an empty list. This avoids forcing extra bullets out of missing evidence. The prompt forbids requests for more information and offers of future work in publication text.

The first live trial exposed unsupported extrapolation on navigation-heavy excerpts. Tightening the prompts addressed the model-side behaviour, but this release does not fix extraction quality. Improving those scraped inputs remains a separate task. Newer model knowledge cannot replace missing article content.

## Accurate cost accounting

Luna rates are now registered for Flex and ordinary processing. USD per million tokens:

| Category | Flex | Ordinary |
|---|---:|---:|
| Uncached input | 0.05 | 0.10 |
| Cached input | 0.005 | 0.01 |
| Cache writes | 0.0625 | 0.125 |
| Output, including billed reasoning | 0.25 | 0.50 |

Ordinary input, cache reads and cache writes are disjoint categories. The calculator subtracts reads and writes from total prompt tokens before pricing ordinary input, then prices reads and writes separately. It clamps counts to the available prompt-token total to prevent invalid accounting from producing negative ordinary input.

Stage wrappers preserve returned tiers and cache-token metadata. Digest and LinkedIn costing receive the actual tier and cache writes. Ordinary-tier cached-input rates for existing Mini and Nano are corrected. Reusing an already stored Mongo AI response still records usage telemetry but does not create a new model-spend entry. These corrections make future stage ledgers more useful; historical ledger discrepancies are not retrospectively rewritten.

## Credit reserve alerts

The daily runner checks estimated OpenAI credit before processing and again on exit, including partial failures. The independent checker reads organisation-wide Costs API data using `OPENAI_API_ADMIN_KEY`, follows pagination, and estimates remaining credit from a reconciled balance/cost baseline. It sends warnings through the existing Slack/Discord webhook transport at **$1 or less**.

This is an estimated prepaid balance, not a live credit-balance API. Top-ups, credit expiry, refunds and billing adjustments require reconciliation. API billing data may arrive late; trial charges may not immediately appear in the estimate. Missing accounting data generates a separate warning rather than being treated as a healthy balance.

Low-balance and unavailable-data alerts are deduplicated per London calendar day after successful delivery. Failed delivery can be retried. The monitor is non-blocking and preserves the daily pipeline's exit status. The final post-deployment dry-run reported $9.98 estimated remaining, with no low-balance condition; this was the reported estimate at that check, not a new billing-dashboard observation.

## Validation evidence

The promoted code passed **63 tests**, with one pre-existing disabled live E2E test skipped. Existing pytest-mark and datetime-deprecation warnings remain unrelated to the change. Tests cover both request paths, payload settings, returned tiers, Flex fallback, malformed/empty/truncated output, generation-aware cache keys, cache-write prices, metadata propagation, cached-response spend and the inclusive $1 alert boundary.

Two small live comparisons produced 20 completed responses across summaries, digest and LinkedIn text without publishing or database writes. In the substantive-excerpt comparison, Luna returned four factual bullets for each article, a complete three-item digest and a usable LinkedIn draft. Its five calls cost **$0.000437925**, compared with **$0.00698925** for Mini: 93.7% lower in this sample. Luna used zero reasoning tokens; one of its five substantive-trial calls fell back to ordinary processing.

Summed call durations in that trial were 59.74 seconds for Luna and 65.84 seconds for Mini. Calls overlapped, so these are not end-to-end run durations. The earlier navigation-heavy trial had slower Luna calls and more fallbacks. These samples do not establish a reliable speed improvement or a population-wide quality advantage. The 67.3% historical fixed-token simulation and the 93.7% small live-trial saving answer different questions and must not be conflated.

## Deployment and recovery

Local, GitHub and server runtime code were aligned at the implementation commit. Only selected model/settings values were changed in the private `.env` files. Credentials, alert baselines, existing schedule and unrelated configuration were preserved. Mode-600 environment backups were stored outside Git under `~/.local/state/lloyds-env-backups/` before updating settings.

The release documentation refresh updates current guides and clearly identifies historical deployment notes. It preserves unpublished local maintenance edits and does not include private CSVs, source excerpts, credentials or trial artifacts in the GitHub release.

For configuration and a focused model rollback, follow [the rollout guide](../deployment/gpt6-luna-rollout.md). Restore the three writing settings to `gpt-5-mini`; remove the new completion cap if restoring the former uncapped configuration. Keep Nano and the compatibility, grounding, costing and balance-monitor fixes. Do not run the publishing script solely to test a rollback.

For a safe accounting check, activate the project environment and run:

```bash
bash scripts/check_openai_balance.sh --dry-run
```

## Follow-up observations

Review the next scheduled runs for complete publication, source fidelity, important-story coverage, retry frequency, end-to-end duration and organisation Costs API spending. A larger, fixed-input quality comparison is needed before asserting stronger editorial quality or faster processing. Strict output schemas, improved source extraction, summary reuse and bounded concurrency remain potential future improvements; they are not claimed as implemented in this release.
